Time Echo System Design

design-doc technical-design unity ecs dots time-manipulation gameplay-systems chrono-aether

Executive Summary

This document details the architecture and implementation of the Time Echo System — the core gameplay mechanic of Chronicles of Aether. The system records player input and entity state for 10 seconds, then spawns an “Echo” entity that replays those actions, enabling single-player cooperative puzzle solving.

Context & Goals

Problem: How to implement a time-recording mechanic that’s deterministic, performant, and supports paradox interactions (player affecting their own echo)?

Goals:

  • Deterministic replay — identical inputs produce identical outputs
  • 60 FPS on 8-year-old hardware (Intel i5-4460, GTX 960)
  • Support 3 simultaneous echoes max
  • Enable paradox mechanics (player-echo interaction)
  • Clean separation from gameplay code for testing

Data Structures

 1// Input frame — 24 bytes, recorded at 60Hz
 2struct InputFrame : IBufferElementData
 3{
 4    public float timestamp;        // Relative to recording start
 5    public uint inputHash;         // Hashed input state (movement, actions)
 6    public float2 moveVector;      // Normalized movement
 7    public bool action1, action2;  // Primary/secondary actions
 8    public float aimAngle;         // Aim direction
 9}
10
11// Entity state snapshot — 48 bytes, recorded at 15Hz
12struct StateSnapshot : IBufferElementData
13{
14    public float timestamp;
15    public float3 position;
16    public quaternion rotation;
17    public float3 velocity;
18    public uint animationStateHash;
19    public byte health;            // For paradox damage calc
20    public ushort flags;           // Grounded, attacking, etc.
21}

Recording Phase

  1. InputRecorderSystem (EarlySimulationSystemGroup)

    • Runs at 60Hz fixed timestep
    • Hashes current input state → InputFrame
    • Appends to TimelineBuffer (circular, 600 frames = 10s)

  2. StateSnapshotSystem (LateSimulationSystemGroup)

    • Runs at 15Hz (every 4 frames)
    • Samples all TimeEchoTracked entities
    • Stores StateSnapshot in parallel buffer

  3. TimelineBuffer — Ring buffer with:

    • head index (oldest valid frame)
    • tail index (next write position)
    • count (valid frames)
    • Auto-evicts oldest when full

Playback Phase

When player activates Time Echo (costs 1 Echo Charge):

  1. EchoSpawnSystem creates EchoEntity with:

    • PlaybackController — drives playback head
    • StateInterpolator — smooths between snapshots
    • GhostVisual — render component with dissolve shader

  2. PlaybackControllerSystem (SimulationSystemGroup)

    • Advances playbackTime at 1x speed
    • Samples InputFrame at current time → feeds to EchoInputComponent
    • Interpolates StateSnapshot → corrects drift every 0.5s

  3. ParadoxDetectorSystem (LateSimulationSystemGroup)

    • Checks player-echo distance < 2m
    • Detects interaction types:
      • Touch — Player touches echo → Chrono Surge (damage boost)
      • Attack — Player hits echo → Temporal Fracture (AoE stun)
      • Sync — Player mirrors echo action → Resonance (resource refund)

Paradox Resolution

Player Action + Echo State = Paradox Effect
─────────────────────────────────────────
Touch          + Idle         → Chrono Surge (2s, +50% dmg)
Touch          + Attacking    → Temporal Fracture (3m radius stun)
Attack (melee) + Any          → Resonance (echo refunds 1 charge)
Ability        + Matching     → Echo Clone (spawns 2nd echo, 50% duration)

Implementation: ParadoxResolver evaluates at collision time, applies effects via StatusEffectSystem, destroys echo on fracture.

Determinism Guarantees

Concern Solution
Float precision Fixed-point math for positions (1/1000 unit)
Physics variance Echo uses kinematic movement; physics disabled
Frame rate Fixed 60Hz simulation step; playback time = frameCount / 60
RNG Shared Unity.Mathematics.Random seeded at recording start
Entity spawns Echo records spawn events; playback re-spawns deterministically

Technical Considerations

Memory Management

  • TimelineBuffer pre-allocated at scene load (600 × 24B + 150 × 48B ≈ 22 KB per tracked entity)
  • Pooled EchoEntity prefabs (max 3 active)
  • No allocations during recording/playback

Save/Load Integration

  • TimelineBuffer serialized with save game
  • Echo charges persist across sessions
  • Paradox unlocks tracked in progression data

Multiplayer (Future)

  • Record input + deterministic sim → replay on clients
  • Echo authority = host; clients receive interpolated transforms
  • Bandwidth: ~2 KB/s per echo (input frames only)
