Lumina Postmortem: Shipping a Solo Godot Game

design-doc postmortem godot solo-dev puzzle mobile web process lessons-learned

Executive Summary

Lumina was my first commercial release as a solo developer. Built in Godot 4 over 5 months, it launched on Steam, itch.io, and web with 12 languages. This postmortem covers the 5-month development cycle.

What Went Right

1. Godot 4 Was Ready

  • GDScript performance was sufficient for 60 FPS light simulation
  • Web export worked out of the box (WASM, 15 MB gzipped)
  • Scene instancing made procedural puzzles trivial
  • AudioServer adaptive layers saved weeks of audio work

2. Scope Discipline

  • 80 puzzles → cut to 60 handcrafted + 20 procedural
  • No combat, no inventory, no dialogue — pure puzzle
  • 3-month prototype validated core loop before art investment
  • Weekly playtests caught difficulty spikes early

3. Daily Challenges = Retention

  • Seeded procedural generation (same seed = same puzzle globally)
  • 40% of players return for daily challenge
  • Zero content cost after generator was built
  • Leaderboards drove community Discord activity

4. Accessibility First

  • Colorblind modes implemented in Week 2 (not polish phase)
  • Zero UI meant no text localization complexity
  • 12 languages via CSV — community translated in 2 weeks
  • Got featured in “Accessible Games” Steam curator

5. Marketing Through Devlogs

  • 15 devlogs on itch.io + Twitter
  • Wishlists: 2,300 at launch (target: 1,000)
  • Press coverage: 3 features (Godot blog, indie showcase, puzzle roundup)
  • Launch revenue covered dev costs in Week 1

What Went Wrong

1. Light Simulation Performance on Mobile

  • Shader complexity underestimated — 30 FPS on 5-year-old phones
  • Fix: Baked light paths for mobile build (precompute in editor)
  • Cost: 2 weeks, separate mobile build pipeline
  • Lesson: Profile on target hardware weekly, not monthly

2. Web Export Memory Leaks

  • Godot 4.1 had WASM memory growth (~50 MB/hour)
  • Workaround: Force reload every 10 puzzles (ugly but worked)
  • Fixed in 4.2 — upgrade path was painful (shader changes)
  • Lesson: Pin engine version for web; test memory over hours

3. Puzzle Difficulty Curve

  • Playtesters were puzzle enthusiasts → curve too steep
  • Post-launch data: 35% drop-off at Puzzle 23 (difficulty spike)
  • Patch 1.1: Added “gentle hint” system (optional, no penalty)
  • Lesson: Test with casual players, not just genre fans

4. Localization Last Minute

  • Assumed Godot CSV import = done
  • Reality: Font fallback, RTL, text expansion broke layouts
  • Fix: Noto Sans fallback, dynamic font sizing, 3 extra weeks
  • Lesson: Integrate real translations during prototype

5. Solo Burnout

  • Months 3-4: 60+ hour weeks, no days off
  • Symptoms: Decision fatigue, code quality dropped, missed bugs
  • Recovery: Took 2 weeks off post-launch; still catching up
  • Lesson: Schedule rest. 1 day/week off is not optional.

Lessons Learned

Technical

  1. Godot + Web = test memory weekly, pin engine version
  2. Shader complexity scales non-linearly — budget for mobile from Day 1
  3. Procedural content needs handcrafted validation (generator made unsolvable puzzles)
  4. ECS not required for small scope — GDScript + nodes was faster to iterate

Design

  1. Pure puzzle games live/die by difficulty curve — test broadly
  2. Daily content is the highest ROI retention mechanic for puzzle games
  3. Zero UI is a superpower for localization and accessibility
  4. Photo mode generated organic social sharing (free marketing)

Process

  1. Solo ≠ all disciplines — hire freelance for weak areas (I hired composer)
  2. Weekly playtests > monthly milestones
  3. Devlogs are marketing — schedule them, don’t squeeze them in
  4. Scope cuts feel bad but ship games — cut early, cut often

Would I Do It Again?

Yes. But differently:

  • Team of 2 (dev + artist) — solo art took 40% of time
  • 6-month timeline — 5 months was too aggressive for polish
  • Mobile-first performance — design for lowest spec target
  • Steam + Web only — skip mobile app stores (update friction, 30% cut)
